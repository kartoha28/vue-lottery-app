## 📖 Опис проєкту

Проєкт **`vue-lottery-app`** є інтерактивним додатком для проведення лотереї серед зареєстрованих учасників. Застосунок реалізовано на базі сучасного фреймворку **Vue 3** з використанням:
- **TypeScript** для строгої типізації моделей учасників (`Participant`) та переможців (`Winner`);
- **Composition API** із синтаксисом `<script setup lang="ts">`;
- Модульного підключення **Bootstrap 5 через SCSS** (імпортовані лише потрібні модулі: кнопки, форми, таблиці, бейджі, модальні вікна);
- Дотримання офіційного [Vue Style Guide](https://ua.vuejs.org/style-guide/);
- Візуального стилю, що відповідає макету з методичних вказівок.

## ✅ Реалізовані вимоги та бізнес-логіка

1. **Блок переможців:**
   - Випадковий вибір за допомогою кнопки `New winner` серед учасників, які ще не стали переможцями.
   - Одночасно може бути **не більше трьох переможців**.
   - Кнопка `New winner` стає неактивною (`disabled`), якщо:
     * Переможців уже 3;
     * Список учасників порожній;
     * Усі наявні учасники вже стали переможцями.
   - Можливість видалення переможця з блоку через клік на `×`.
   - **Автоматична синхронізація:** якщо учасника видаляють із таблиці, і він був переможцем, він автоматично видаляється і з блоку переможців.

2. **Форма реєстрації нових учасників:**
   - Усі поля обов'язкові (`Name`, `Date of Birth`, `Email`, `Phone number`).
   - `Name`: обов'язкове поле.
   - `Date of Birth`: `input type="date"`, перевірка, що дата народження не є в майбутньому.
   - `Email`: валідація регулярним виразом та перевірка на унікальність без урахування регістру (`toLowerCase()`).
   - `Phone number`: перевірка регулярним виразом на формат `+380XXXXXXXXX` (код країни та 9 цифр).
   - **Жодних `alert()`:** помилки виводяться червоним кольором під відповідними полями вводу.
   - Успішне поле підсвічується зеленою рамкою та галочкою `✓`.
   - При натисканні `Enter` форма надсилається автоматично завдяки `@keydown.enter`.
   - При очищенні форми після натискання `Save` валідація не викликає помилкових червоних повідомлень.

3. **Таблиця учасників, пошук та сортування:**
   - Відображаються стовпці: `#`, `Name`, `Date of Birth`, `Email`, `Phone number`, `Actions`.
   - **Пошук (`SearchBar`):** затримка (debounce) 300 мс за допомогою `watch`, фільтрація за іменем.
   - **Сортування:** за іменем (A-Z) та датою народження. Повторний клік перемикає напрямок (зростання / спадання) з візуальною іконкою напрямку.
   - Фільтрація та сортування працюють разом через `computed` без мутації вихідного масиву.

4. **Модальні вікна:**
   - **Редагування даних:** модальне вікно з передзаповненими полями учасника, повною валідацією (власний email учасника не вважається дублікатом) та кнопкою «Оновити дані».
   - **Підтвердження видалення:** модальне вікно із запитом *"Ви дійсно бажаєте видалити учасника "{name}", "{email}"?"* та кнопками «Так» / «Ні».
   - Закриття модального вікна по клавіші `Esc` через модифікатор клавіатури.

5. **Збереження даних у `localStorage`:**
   - Реалізовано збереження учасників та переможців за допомогою `watch` з опцією `{ deep: true }`.
   - Відновлення даних при старті додатку в хуку `onMounted()`.

## ❓ Відповіді на всі 22 контрольні запитання

### 1. Що таке обчислювані властивості (computed) у Vue.js і чим вони відрізняються від звичайних методів?
**Обчислювані властивості (`computed`)** — це реактивні значення, які обчислюються декларативно на основі інших реактивних джерел даних (`ref`, `reactive`).  
**Відмінності від методів:**
- **Кешування:** значення `computed` кешується на основі своїх реактивних залежностей. Якщо залежності не змінювалися, багаторазове звернення повертає вже готове збережене значення без повторного виконання функції.
- **Методи:** викликаються заново при кожному рендерингу компонента, незалежно від того, чи змінилися дані всередині них.

### 2. Як працює кешування обчислюваних властивостей і коли значення перераховується?
Під час першого виклику `computed`-властивості Vue відстежує, до яких саме реактивних змінних відбулося звернення (механізм *dependency tracking*). Отриманий результат зберігається в кеші. Якщо жодна зі змінних-залежностей не змінилася, повертається значення з кешу. Як тільки хоча б одна залежність змінює своє значення, кеш позначається як *dirty* (застарілий), і при наступному зверненні функція обчислюється повторно.

### 3. Чи можна змінювати значення обчислюваної властивості? Як реалізувати writable computed?
За замовчуванням `computed` доступний лише для читання (*read-only*). Проте його можна зробити записуваним (**writable computed**), передавши об'єкт із функціями `get()` та `set(newValue)`:
```typescript
const fullName = computed({
  get() {
    return `${firstName.value} ${lastName.value}`
  },
  set(newValue: string) {
    const parts = newValue.split(' ')
    firstName.value = parts[0] ?? ''
    lastName.value = parts[1] ?? ''
  }
})
```

### 4. Які існують способи оголошення обробників подій у Vue? Чим відрізняється inline-обробник від обробника-методу?
У Vue підтримуються два способи:
1. **Вбудований (inline) обробник:** безпосереднє виконання виразу JavaScript у шаблоні, наприклад: `@click="count++"` або `@click="deleteItem(item.id, $event)"`.
2. **Обробник-метод:** передача посилання на функцію без круглих дужок, наприклад: `@click="handleClick"`. У цьому разі нативний об'єкт `event` автоматично передається першим аргументом.

### 5. Для чого призначені модифікатори подій (.prevent, .stop, .once) та ключові модифікатори (.enter, .esc)? Наведіть приклади використання.
Модифікатори подій дозволяють декларативно керувати поведінкою DOM-подій без написання рутинного коду `event.preventDefault()` чи `event.stopPropagation()`:
- `.prevent` — викликає `event.preventDefault()` (наприклад, запобігає перезавантаженню сторінки при відправці форми: `<form @submit.prevent="save">`).
- `.stop` — викликає `event.stopPropagation()` (запобігає спливанню події вгору по дереву DOM: `<button @click.stop="handleClick">`).
- `.once` — спрацьовує лише один раз за життєвий цикл елемента (`<button @click.once="claimBonus">`).
- `.enter` — слухає натискання клавіші Enter (`<input @keydown.enter="submitForm" />`).
- `.esc` — слухає натискання клавіші Escape (`<div @keydown.esc="closeModal">`).

### 6. Як працює директива v-model і яким синтаксичним записом (:value та @input) її можна замінити для звичайного текстового поля?
Директива `v-model` забезпечує двостороннє зв'язування даних (*two-way data binding*) між станом у скрипті та елементом форми. Для звичайного текстового поля запис:
```vue
<input v-model="text" />
```
є синтаксичним цукром для:
```vue
<input :value="text" @input="text = ($event.target as HTMLInputElement).value" />
```

### 7. Як використовувати v-model з різними елементами форми: checkbox, radio, select, textarea?
- **Checkbox:**
  * Одиночний: зв'язується з логічним значенням `boolean` (`<input type="checkbox" v-model="isChecked" />`).
  * Група checkbox'ів: прив'язується до масиву `string[]`, куди додаються/видаляються значення атрибута `value`.
- **Radio:** зв'язується зі змінною `string` або `number`; активується той радіо-баттон, чиє `value` збігається зі змінною (`<input type="radio" value="male" v-model="gender" />`).
- **Select:** зв'язується зі змінною для обраного `<option>` (або з масивом у разі `<select multiple>`).
- **Textarea:** зв'язується зі стрічковою змінною (`<textarea v-model="bio" />`), замінюючи інтерполяцію всередині тегу.

### 8. Для чого призначені модифікатори v-model: .lazy, .number, .trim?
- `.lazy` — синхронізує значення не по події `input`, а по події `change` (тобто після втрати фокусу полем або натискання Enter).
- `.number` — автоматично приводить введений рядок до числа за допомогою `parseFloat()` (якщо введення не є числом, повертається початковий рядок).
- `.trim` — автоматично обрізає пробіли на початку та в кінці введеного тексту.

### 9. Як реалізувати валідацію полів форми (обов’язкові поля, regexp для e-mail та телефону, перевірка дати) та вивести помилки користувачу без використання alert?
1. Створюється реактивний об'єкт стану помилок `errors = reactive({ email: '', phone: '' })` та об'єкт відстеження взаємодії `touched = reactive({ email: false })`.
2. Пишуться функції перевірки регулярними виразами:
   - Email: `^[^\s@]+@[^\s@]+\.[^\s@]+$`
   - Телефон: `^\+380\d{9}$`
   - Дата: `inputDate <= today`
3. У шаблоні під кожним полем виводиться блок з помилкою через директиву `v-if="touched.fieldName && errors.fieldName"`, застосовуючи класи валідації `:class="{ 'is-invalid': !!errors.fieldName }"`. Завдяки цьому помилки з'являються безпосередньо в інтерфейсі користувача.

### 10. Як очистити форму після збереження так, щоб при цьому не спрацювала валідація полів?
Необхідно одночасно скинути як самі значення моделі форми (`formData`), так і прапорці взаємодії з полями (`touched`) та текст помилок (`errors`). Якщо валідація орієнтується на комбінацію `touched.field && errors.field`, то при скиданні `touched[key] = false` та `errors[key] = ''` шаблон залишається в чистому первинному стані без червоних повідомлень.

### 11. Що таке props? У якому напрямку передаються дані між батьківським і дочірнім компонентами?
**Props (вхідні параметри)** — це кастомні атрибути, які компонент оголошує для прийняття зовнішніх даних від свого батьківського компонента.  
Потік даних у Vue є **односпрямованим зверху вниз (one-way data flow)**: батьківський компонент передає дані дочірньому через props.

### 12. Чому не можна напряму змінювати props у дочірньому компоненті? Як правильно поступати, якщо потрібно змінити передане значення?
**Чому не можна:** це порушує принцип односпрямованого потоку даних і робить стан застосунку непередбачуваним. При кожному повторному рендерингу батьківського компонента локальні мутації пропсів у дочірньому будуть перезаписані.  
**Правильні підходи:**
1. Якщо значення потрібне як початкове для локального стану: створити локальний `ref`: `const localValue = ref(props.initialValue)`.
2. Якщо значення потрібно модифікувати в батьківському компоненті: дочірній компонент надсилає подію через `emit('update:value', newValue)`, а батько сам змінює стан.

### 13. Як типізувати props за допомогою TypeScript (defineProps або опція props) і як задати значення за замовчуванням та обов’язковість?
У Composition API з `<script setup>` використовується макрос `defineProps<T>()` на рівні типів:
```typescript
interface Props {
  title: string        // обов'язковий prop
  disabled?: boolean   // необов'язковий prop
  count?: number
}

// Задання значень за замовчуванням за допомогою withDefaults
const props = withDefaults(defineProps<Props>(), {
  disabled: false,
  count: 0
})
```

### 14. Як дочірній компонент повідомляє батьківському про подію? Для чого використовується emit (defineEmits) і як типізувати події?
Дочірній компонент ініціює кастомну подію через функцію `emit`. Батьківський компонент підписується на неї через директиву `@event-name="handler"`.  
Для типізації подій використовується макрос `defineEmits`:
```typescript
const emit = defineEmits<{
  (e: 'filter-by-name', query: string): void
  (e: 'remove-winner', id: string): void
}>()

// Виклик події
emit('filter-by-name', 'Олександр')
```

### 15. Як організувати двостороннє зв’язування v-model на власному компоненті?
У Vue 3 `v-model` за замовчуванням використовує prop `modelValue` та подію `update:modelValue`:
```vue
<!-- Дочірній компонент MyInput.vue -->
<script setup lang="ts">
defineProps<{ modelValue: string }>()
const emit = defineEmits<{ (e: 'update:modelValue', val: string): void }>()
</script>

<template>
  <input :value="modelValue" @input="emit('update:modelValue', ($event.target as HTMLInputElement).value)" />
</template>
```
У батьківському компоненті використовується: `<MyInput v-model="userName" />`. Також можна використовувати зручний макрос `defineModel()` у Vue 3.4+.

### 16. Що таке слоти (slots)? Чим іменовані слоти відрізняються від слота за замовчуванням і як вони допомагають створити компонент Modal?
**Слоти (`<slot>`)** — це механізм розподілу контенту, що дозволяє батьківському компоненту передавати довільну розмітку всередину дочірнього компонента.
- **Слот за замовчуванням (`default`):** приймає весь контент, який не прив'язаний до конкретного імені (`<slot />`).
- **Іменовані слоти (`named slots`):** оголошуються через `<slot name="header" />`, `<slot name="footer" />` та заповнюються в батька через директиву `v-slot:header` (або `#header`).
- **Застосування у Modal:** дозволяє створити гнучкий скелет діалогового вікна, де компонент модалки відповідає за затемнення, центрування, рамки та анімації, а користувач вільно кастомізує заголовок (`#header`), контент (`#body`) і кнопки дій (`#footer`).

### 17. Що таке watchers (спостерігачі)? Чим watch відрізняється від computed і в яких випадках доцільно використовувати кожен з них?
**Watchers (`watch`)** — це функції, які виконують побічні ефекти (*side effects*) у відповідь на зміну реактивних даних.  
**Відмінності:**
- `computed` є чистим декларативним обчисленням значення без побічних дій. Воно синхронне та повертає кешоване значення.
- `watch` служить для виконання імперативних асинхронних дій або побічних операцій (запити до сервера, робота з `localStorage`, таймери/debounce, запис у DOM).  
**Коли використовувати:**
- `computed` — коли потрібно розрахувати відфільтрований або відсортований список, статус кнопки тощо.
- `watch` — коли на зміну даних треба зберегти стан у `localStorage` або виконати пошуковий запит із затримкою 300 мс.

### 18. Для чого призначені опції deep та immediate у watch? Чим watchEffect відрізняється від watch?
- `immediate: true` — викликає колбек-функцію спостерігача негайно при створенні компонента, не чекаючи першої зміни значення.
- `deep: true` — примушує Vue рекурсивно відстежувати зміни всіх вкладених властивостей всередині масивів чи об'єктів.
- **`watchEffect` vs `watch`:**
  * `watch` явно вказує джерела для відстеження і надає доступ до `(newValue, oldValue)`. За замовчуванням є лінивим (*lazy*).
  * `watchEffect` автоматично відстежує всі реактивні властивості, до яких відбулося звернення всередині його тіла, і запускається негайно при створенні.

### 19. Як за допомогою watcher реалізувати збереження списку учасників у localStorage та відновлення його при завантаженні застосунку?
1. **Збереження:** оголошується `watch` на реф `participants` з опцією `deep: true`:
```typescript
watch(
  participants,
  (newParticipants) => {
    localStorage.setItem('lottery_participants', JSON.stringify(newParticipants))
  },
  { deep: true }
)
```
2. **Відновлення:** у хуку життєвого циклу `onMounted` зчитується збережений рядок із `localStorage` та парситься через `JSON.parse`:
```typescript
onMounted(() => {
  const saved = localStorage.getItem('lottery_participants')
  if (saved) {
    participants.value = JSON.parse(saved)
  }
})
```

### 20. Які принципи слід враховувати при поділі застосунку на компоненти? Що таке багаторазовий (reusable) компонент?
**Принципи поділу:**
- **Єдина відповідальність (Single Responsibility Principle):** кожен компонент має відповідати за одну конкретну задачу (наприклад, тільки пошуковий рядок або тільки модальне вікно).
- **Слабке зв'язування (Low Coupling) та висока згуртованість (High Cohesion):** компонент мінімально залежить від зовнішнього контексту, приймаючи все через `props` і повідомляючи про події через `emit`.
- **Повторне використання:** виділення повторюваних елементів (кнопки, поля вводу, бейджі) в окремі компоненти.
- **Багаторазовий (reusable) компонент** — це компонент, який не містить специфічної бізнес-логіки конкретної сторінки і може бути використаний у будь-якому місці застосунку з різними параметрами та слотами (наприклад, `AppButton`, `AppInput`, `AppModal`).

### 21. Як реалізувати сортування та фільтрацію списку учасників у таблиці за допомогою обчислюваних властивостей?
Створюється обчислювана властивість `displayedParticipants`, яка бере копію початкового масиву, спочатку застосовує фільтр, а потім сортує результат:
```typescript
const displayedParticipants = computed(() => {
  let result = [...participants.value]

  // 1. Фільтрація
  if (searchQuery.value) {
    const q = searchQuery.value.toLowerCase()
    result = result.filter(p => p.name.toLowerCase().includes(q))
  }

  // 2. Сортування
  if (sortField.value) {
    const dir = sortDirection.value === 'asc' ? 1 : -1
    result.sort((a, b) => {
      if (sortField.value === 'name') {
        return a.name.localeCompare(b.name, 'uk') * dir
      }
      if (sortField.value === 'dateOfBirth') {
        return a.dateOfBirth.localeCompare(b.dateOfBirth) * dir
      }
      return 0
    })
  }

  return result
})
```
Це гарантує, що оригінальний масив `participants` не мутується, а таблиця автоматично реактивно оновлюється.

### 22. Яка різниця між Options API та Composition API? Які переваги надає кожен із підходів?
- **Options API:** класичний підхід Vue 2, де логіка компонента розбита на секції: `data()`, `methods`, `computed`, `watch`, `mounted`.
  * *Переваги:* чітка, сувора структура, яка легко сприймається початківцями.
  * *Недоліки:* логіка однієї фічі «розмазується» по різних опціях компонента; складність повторного використання коду (проблеми mixins).
- **Composition API:** сучасний підхід Vue 3, де логіка групується навколо конкретних функцій і сутностей за допомогою `ref`, `computed`, `watch` всередині `<script setup>`.
  * *Переваги:*
    1. Відмінна підтримка **TypeScript** без потреби складних декораторів чи неявного `this`;
    2. Зручне винесення логіки в незалежні компоновані функції (**Composables**);
    3. Компактний синтаксис та краща оптимізація при збірці (Tree-shaking).
